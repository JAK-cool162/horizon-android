1. THE MODEL IN ONE PICTURE
--------------------------------------------------------------------------------

There are two kinds of mods:

  .hmod   A sandboxed WebAssembly mod. Written in Rust with `horizon-mod-sdk`,
          compiled to wasm32, packed as a .hmod. The game loads it AT RUNTIME:
          import the file, turn it on, done. NO APK REBUILD. It can only do what
          its declared capabilities allow (HUD text, chat, its own screens,
          storage, players, blocks...). It cannot touch the game's code, the GPU
          or the phone.

  .hnmod  A native mod: Rust source that is compiled INTO the game (horizon-mixins
          injects it at "hook points"). Full power, but every change needs a new
          APK build (the app's Build APK button, on your GitHub fork).

The MOD BRIDGE connects them. A .hnmod defines an API of its own (a name such as
`extras`, functions, values, events, asks). A .hmod calls it by name:

    .hmod  --bridge::call("extras", "command", "give Alex minecraft:bread 8")-->
    game   --> the .hnmod that serves "extras" runs it as native code
    .hnmod --answer--> game --> .hmod's bridge_reply(id, ...)

So: build the API .hnmod ONCE into the APK; after that, any number of .hmod mods
use it and load without rebuilding. The Extras API (`extras_api.hnmod`) is the
general-purpose one, built into Horizon Android dev APKs from version code 1008.

Which to write? Write a .hmod whenever the SDK or the Extras API can do it. Write
(or extend) a .hnmod only for something no API offers yet.

2. WHAT YOU NEED
--------------------------------------------------------------------------------

On a computer (Windows, macOS or Linux):
  - Rust (rustup, stable), and the WebAssembly target:
        rustup target add wasm32-unknown-unknown
  - The mod tool `cargo horizon-mod`, from THIS fork (upstream's has no bridge):
        cargo install --locked --git https://github.com/JAK-cool162/horizon-android \
            --branch android cargo-horizon-mod
    (or, in a clone of the repository: cargo run -p cargo-horizon-mod -- horizon-mod <command>)

On the phone:
  - A Horizon Android dev APK with the Extras API built in (version code 1008 or
    later; 1009 is current). It serves mod API level 9 (the bridge) and
    `extras` version 3.
  - A 64-bit (arm64) phone: sandboxed code mods need a 64-bit APK.

3. MAKING A MOD PROJECT
--------------------------------------------------------------------------------

    cargo horizon-mod new my_mod --template code
    cd my_mod

IMPORTANT: point the SDK at this fork. In my_mod/Cargo.toml set:

    [dependencies]
    horizon-mod-sdk = { git = "https://github.com/JAK-cool162/horizon-android", branch = "android" }
    serde_json = "1"          # for the Extras API's JSON (optional but usual)

(With a local clone: `horizon-mod-sdk = { path = "<clone>/crates/horizon-mod-sdk" }`,
or `cargo horizon-mod new my_mod --sdk-path <clone>/crates/horizon-mod-sdk`.)

The crate must be a cdylib (the template already says so):

    [lib]
    crate-type = ["cdylib"]

Commands, run in the mod folder:

    cargo horizon-mod build     # -> target/horizon-mod/<id>.hmod
    cargo horizon-mod test      # runs tests/*.toml in the sandbox (section 8)
    cargo test                  # your ordinary Rust unit tests (on the computer)
    cargo horizon-mod check <file.hmod>   # what the app checks before installing

4. horizon-mod.toml (THE MANIFEST)
--------------------------------------------------------------------------------

Client mod (runs in the player's game window):

    id = "video_settings"           # lowercase letters, digits, _ ; unique
    name = "Video Settings+"
    version = "0.1.0"
    description = "What it does, for the player."
    authors = ["Your name"]
    api = "0.1"                     # client mods: "0.1" (or "0.2" with content)
    side = "client"
    capabilities = ["command", "ui", "bridge"]
    experimental = ["ui", "bridge"] # every experimental capability you use

Server mod (runs where the world is simulated: single player's own server
thread, LAN host, dedicated server):

    id = "spawn_guard"
    name = "Spawn Guard"
    version = "0.1.0"
    description = "..."
    authors = ["..."]
    api = "0.3"                     # server mods are always "0.3"
    side = "server"
    capabilities = ["players", "bridge"]
    experimental = ["bridge"]

Capabilities (what the player is told the mod may do):

  game-read  client  position, health, time, raycast         (interface game)
  chat       client  show chat lines                          (chat)
  hud        client  a text panel in a corner                 (hud)
  storage    both    the mod's own small files                (storage)
  command    client  run commands as the player               (command)
  ui         client  own screens and a settings page   EXPERIMENTAL (ui)
  render     client  HUD shapes, text, sprites, zoom,
                     shake, frame statistics           EXPERIMENTAL (render)
  input      client  keys, clicks, the use button      EXPERIMENTAL (input)
  recipes    client  recipes and items                 EXPERIMENTAL (recipes)
  players    server  online players, tell, broadcast          (players)
  world      server  read, set and break blocks               (world)
  bridge     both    the APIs native mods add          EXPERIMENTAL (bridge)

Rules the game enforces (a mod that breaks one is refused with the reason):
  - Every interface the compiled wasm imports needs its capability declared.
  - Experimental capabilities must also be listed in `experimental`.
  - Server mods with this SDK always import `players`: declare "players".
  - A capability of the other side is refused (hud on a server mod...);
    `storage` and `bridge` are allowed on both.

5.1 Client mod skeleton

    use horizon_mod_sdk::{Mod, Registration, export_mod, hud, bridge};

    struct MyMod { /* state */ }

    impl Mod for MyMod {
        fn init() -> Result<(Self, Registration), String> {
            Ok((MyMod {}, Registration::new().command("hello").on_tick()))
        }
        fn command(&mut self, name: &str, args: &str) -> Result<Option<String>, String> {
            Ok(Some(format!("/{name} {args}")))   // feedback; Err(..) shows red
        }
        fn tick(&mut self, tick: u64) {}
    }
    export_mod!(MyMod);

  Mod trait (all but init optional; a hook is called only if registered):
    fn init() -> Result<(Self, Registration), String>
    fn tick(&mut self, tick: u64)                       // Registration::on_tick()
    fn frame(&mut self, seconds: f32)                   // on_frame()
    fn command(&mut self, name: &str, args: &str) -> Result<Option<String>, String>
                                                        // command("name")
    fn chat(&mut self, text: &str)                      // on_chat()
    fn ui_select(&mut self, id: u32, row: u32)          // a widget clicked (ui)
    fn ui_closed(&mut self)                             // its screen left (ui)
    fn ui_settings_opened(&mut self)                    // Options > Mods > Settings
    fn bridge_reply(&mut self, id: u64, api: &str, function: &str,
                    answer: Result<&str, &str>)         // bridge
    fn bridge_event(&mut self, api: &str, name: &str, data: &str)   // bridge
    fn bridge_ask(&mut self, api: &str, name: &str, data: &str) -> Option<String>

  Client interfaces (module paths under horizon_mod_sdk::): game, chat, hud,
  storage, command, ui, render, input, recipes, browser, log, bridge.
  Helpers: horizon_mod_sdk::info(msg), horizon_mod_sdk::warn(msg) -> the game log.

5.2 Server mod skeleton

    use horizon_mod_sdk::server::{ServerMod, Registration, Player, Args, BlockPos, players, world};

    struct MyServerMod;

    impl ServerMod for MyServerMod {
        fn init() -> Result<(Self, Registration), String> {
            Ok((MyServerMod, Registration::new().on_joins().command("hi")))
        }
        fn player_joined(&mut self, p: &Player) {
            players::tell(&p.id, &format!("Welcome, {}!", p.name));
        }
        fn command(&mut self, p: &Player, name: &str, args: &Args)
            -> Result<Option<String>, String> { Ok(Some("hi".into())) }
    }
    horizon_mod_sdk::export_server_mod!(MyServerMod);

  ServerMod trait:
    fn init() -> Result<(Self, Registration), String>
    fn tick(&mut self, tick: u64)                                     // on_tick()
    fn player_joined(&mut self, p: &Player); fn player_left(..)       // on_joins()
    fn chat(&mut self, p: &Player, text: &str)                        // on_chat()
    fn command(&mut self, p: &Player, name: &str, args: &Args) -> Result<Option<String>, String>
    fn block_broken(&mut self, p: &Player, pos: BlockPos, state: &str)  // on_blocks()
    fn block_placed(&mut self, p: &Player, pos: BlockPos, state: &str)  // on_blocks()
    fn block_used(&mut self, player: &str, dimension: &str, pos: BlockPos,
                  state: &str, item: Option<&str>)  // on_blocks(); API level 8;
                                                    // arrives a tick after the click
    fn bridge_reply / bridge_event / bridge_ask     // as for client mods

  Player (server): id (UUID string "xxxxxxxx-xxxx-..."), name, x, y, z,
  dimension ("minecraft:overworld"...), game_mode, health.
  BlockPos { x, y, z }. Block states are strings: "minecraft:oak_log[axis=y]".

  Typed command arguments:
    Registration::new().command_with("pay", [Argument::player("to"),
        Argument::integer("amount", Some(1), None), Argument::text("note").optional()])
    then args.player("to"), args.integer("amount"), args.string("note"),
    args.number(..), args.boolean(..), args.block_pos(..), args.text() (the raw line).
    Argument kinds: word, text (rest of line, last only), integer(min,max),
    number, boolean, player (name, @s, @p), block_pos (x y z, ~ allowed).

  Server interfaces: players (online, tell, broadcast), world (get_block,
  get_biome, set_blocks, break_blocks), storage, log, bridge.

6. THE MOD BRIDGE (capability `bridge`, mod API level 9)
--------------------------------------------------------------------------------

Functions (horizon_mod_sdk::bridge):

  bridge::version(api: &str) -> Option<u32>
      The version of `api` a native mod serves in THIS game; None = not installed.
      Works from init(). Always check it and tell the player what to install.

  bridge::get(api: &str, key: &str) -> Option<String>
      A value the native API published (synchronous, as of this call).

  bridge::call(api: &str, function: &str, args: &str) -> Result<u64, String>
      Queues a call; returns its id at once. The native mod runs it BEFORE THE
      NEXT TICK'S MOD HOOKS (so server helpers work), and the answer arrives as
          bridge_reply(id, api, function, Ok(answer) | Err(why))
      Err now (nothing queued) for: api/function name > 64 bytes, args > 64 KiB,
      more than 64 calls in one hook call.
      If no native mod serves `api`, the reply is Err("no native mod serves the
      API <api>: install the .hnmod that adds it").

Things the native API sends you (only to mods with capability `bridge`):

  bridge_event(api, name, data)
      Something happened (after it happened). Delivered before the next tick's hooks.

  bridge_ask(api, name, data) -> Option<String>
      A question AT ONCE, inside the game's tick, about something happening now.
      Return None to let it be, or the answer the API documents (for extras:
      "cancel" or "cancel <reason>"). The game WAITS for you: keep it fast, no
      loops over big data, no bridge calls needed to answer.

Where calls run: in the game the mod runs in. A server mod's calls are answered
by the server's native mods (server thread / dedicated server); a client mod's by
the window's. Values and subscriptions are per game.

7. EXTRAS API 3 REFERENCE (native API name: "extras", version 3)
--------------------------------------------------------------------------------

Check: bridge::version("extras") >= Some(3) (2 for server-only features).
Since 3.1 (same version number 3), changing things needs the player's permission: 7.0.
Arguments and answers are JSON text, except `command`'s argument (a plain line).
Players are named by UUID (as players::online gives them) or by name.
Mods using Extras can do what a server operator can: say so in your description.

7.0 PERMISSIONS (Extras API 3.1, APK 1010 and later)
  Some functions need the player's permission, per mod and group:
    commands  -> command
    players   -> tell, actionbar, sidebar, tablist, nickname, xp, levels, sleep_ignored
    control   -> subscribe to any ASK (break_block, use_block, ...): it can cancel
    settings  -> set_option
  Reading needs none (players, options, shader_packs, values, events).
  Until allowed, the call's reply is Err("<mod_id> needs your permission to ...:
  allow it in Options > Mods > Extras API > Settings"), and the operators (in single
  player: the player) are told once. The player flips the switch on that page.
  YOUR MOD MUST HANDLE THIS: show/log the Err text to the player, and try again
  later (e.g. every 100 ticks) for things it needs from the start (subscribe).
  Dedicated servers: the admin edits horizon-mods/.horizon-mod-data/extras_api/permissions
  (lines "<mod_id> <group> allow").

7.1 SERVER MOD FUNCTIONS (call from a server mod)

  command      args: a command line, with or without "/"
               Runs it as the server console (permission level 4, from the
               Overworld spawn), no output captured. Ok("") if it ran, Err if
               it failed. Example: bridge::call("extras","command","give Alex minecraft:bread 8")
               Covers give, effect, tp, summon, particle, playsound, title, time,
               weather, setblock, fill, scoreboard, ... (all vanilla commands).

  subscribe    args: JSON list of event/ask names, e.g. ["player_join","break_block"]
  unsubscribe  answer: the same list. Unknown name -> Err. Subscribe in init().

  players      args: "" ; answer: JSON list of
               {"player","name","permission"(0-4),"dimension","x","y","z",
                "game_mode"(0 survival,1 creative,2 adventure,3 spectator),"health"}

  tell         {"player":"Alex","text":"hello"}      chat line to one player
  actionbar    {"player":"Alex","text":"hello"}      text over the hotbar
  sidebar      {"player":"Alex","title":"Stats","lines":["a",{"left":"Kills","right":"3"}]}
               up to 15 lines; {"player":"Alex","title":null} removes it.
               Only that player sees it; send again when they rejoin.
  tablist      {"player":"Alex","header":"My Server","footer":"have fun"}
  nickname     {"player":"Alex","name":"Captain"}   ("name":null resets)
  xp           {"player":"Alex","points":50}        experience (Mending first)
  levels       {"player":"Alex","levels":-3}        add or take levels
  sleep_ignored {"player":"Alex","ignored":true}    night doesn't wait for them

  Answers: Ok("") on success; Err("the player is not here") / Err("<who> is not online").

7.2 CLIENT MOD FUNCTIONS (call from a client mod: the window's settings)

  options      args: "" ; answer JSON:
               {"render_distance","simulation_distance","max_fps","graphics",
                "clouds","particles","smooth_lighting","entity_shadows",
                "biome_blend","mipmap_levels","entity_distance","gamma","fov",
                "view_bobbing","shader_pack"}
  set_option   {"name":"<option>","value":<value>} ; applies as Video Settings
               would, saves options.txt, answers with the new `options` JSON.
               Ranges: render_distance 2-32, simulation_distance 5-32,
               max_fps 10-260 (260 = unlimited), graphics "fast"|"fancy"|"fabulous"
               (applies that preset), clouds "false"|"fast"|"true",
               particles 0 all|1 decreased|2 minimal, smooth_lighting bool,
               entity_shadows bool, biome_blend 0-7, mipmap_levels 0-4,
               entity_distance 0.5-5, gamma 0-10 (1 = slider max; above = fullbright),
               fov 30-110, view_bobbing bool, shader_pack "" or a file from
               shader_packs.
  shader_packs args: "" ; answer: JSON list of {"file","title"} in shaderpacks/.

7.3 VALUES (bridge::get("extras", key)) - on the server
  tps   ticks per second kept up, one decimal ("20.0")
  mspt  milliseconds per tick ("3.1")

7.4 EVENTS (subscribe, then bridge_event("extras", name, data)) - server
  player_join   {"player","name"}
  player_leave  {"player","name"}
  player_death  {"player","cause"}   cause = death message key ("death.attack.lava") or null
  mob_killed    {"player","entity","kind"}   a mob the player's melee blow killed
  item_dropped  {"player","item","count"}

7.5 ASKS (subscribe, then answer bridge_ask("extras", name, data)) - server
  Answer None = allow. "cancel" = stop it. "cancel <reason>" = stop and tell
  the player <reason>. The first mod that cancels wins.

  break_block    player fields* + {"x","y","z","block"}  block = full state string
  use_block      player fields* + {"x","y","z","face":[dx,dy,dz],"block"}
                 asked once per hand per right click
  attack_entity  player fields* + {"entity","kind","at":[x,y,z]}
  pickup_item    {"player","item","count"}; cancelled -> stack waits 10 ticks
  command        {"player","name","command"} (no slash; ANY command a player
                 sends); "cancel <reason>" sends <reason> as the answer
  explosion      {"dimension","x","y","z","blocks"}; cancelled -> breaks no block
                 (entities are still hurt)

  * player fields = {"player","name","permission","dimension","x","y","z",
    "game_mode","health"} of the player doing it.

8. TESTING WITHOUT A PHONE (SANDBOX SCRIPTS)
--------------------------------------------------------------------------------

Put TOML scripts in tests/*.toml and run `cargo horizon-mod test`. The mod runs in
the real sandbox; the native APIs are faked by the script.

    # Fake the Extras API (version, published values, answers per function).
    [bridge.extras]
    version = 3
    values = { tps = "20.0", mspt = "3.1" }
    replies = { command = "", subscribe = '["break_block"]' }   # Ok(answer)
    errors  = { give = "Unknown item" }                          # Err(answer)
    # A function in neither -> Err("extras has no function <f>").
    # An API not listed -> Err("no native mod serves the API ...").

    [[step]]
    join = "Alex"                                  # server mods: a player joins
    expect.calls = ["extras subscribe [\"break_block\"]"]   # "api function args"
    expect.told = ["Alex: Welcome!"]               # players::tell lines

    [[step]]
    bridge-ask = { api = "extras", name = "break_block", data = '{"x":1,"y":64,"z":1,"permission":0,"dimension":"minecraft:overworld"}' }
    expect.answer = "cancel This area is protected"   # "" = no answer (None)

    [[step]]
    bridge-event = { api = "extras", name = "player_death", data = '{"player":"...","cause":null}' }

    [[step]]
    command = "tps"
    expect.feedback = "20.0 TPS"                   # or expect.error = "..."

Other step fields: ticks, frames, chat, command, join, leave, as = "Name",
break = {x,y,z,state}, place = {x,y,z,state}, use = {x,y,z,state,item},
blocks = [{x,y,z,state}] (world before the step), player = {x,y,z,...},
clock = {...}, reload = true. Expect fields: chat, feedback, error, told,
broadcast, panel, corner, blocks, drops, calls, answer, commands, stopped.
Bridge answers arrive within the same step (the game answers a tick later).

9. INSTALLING ON THE PHONE
--------------------------------------------------------------------------------

1. Build: cargo horizon-mod build  ->  target/horizon-mod/<id>.hmod
2. Copy the .hmod to the phone.
3. Horizon launcher: Mods > Import file > pick the .hmod.
4. Installed > turn it on (the player sees its capabilities first).
5. In game: Options > Mods lists it; a `ui` mod's Settings button opens its page.
The launcher names an imported mod <id>.hmod and switches it by its id.

10. RULES, LIMITS AND MISTAKES TO AVOID
--------------------------------------------------------------------------------

- Always check bridge::version("extras") and degrade gracefully with a message.
- Subscribe to events/asks in init(); only to what you need (asks cost time).
- bridge_ask must be fast and must not wait for anything.
- Bridge answers come a tick later: keep state (a map from call id to what it
  was for) and react in bridge_reply.
- Storage keys: [a-z0-9_.-], 1-64 characters (no "/"); a limited number of keys
  and bytes per mod: store lists in one key rather than one key per player.
- Server mods: declare "players"; api = "0.3"; side = "server".
- Client mods: ui/render/input/recipes/bridge are experimental: list them.
- Text limits: ui/hud strings up to 256 characters; up to 64 widgets a screen;
  8 chat lines per call; up to 16 HUD panel lines.
- Fuel: each hook has an instruction budget; a runaway loop stops the mod
  (it is turned off with the reason).
- JSON: use serde_json (it compiles for wasm32).
- Never parse player-typed text as JSON for Extras without escaping:
  build JSON with serde_json::json!.
- Don't promise device performance: test on the phone.

11.1 Server: protect spawn with asks (spawn-guard)

    use horizon_mod_sdk::bridge;
    use horizon_mod_sdk::server::{Registration, ServerMod};
    use serde_json::Value;

    struct Guard;
    impl ServerMod for Guard {
        fn init() -> Result<(Self, Registration), String> {
            if bridge::version("extras").is_some_and(|v| v >= 2) {
                bridge::call("extras", "subscribe", r#"["break_block","use_block"]"#)?;
            }
            Ok((Guard, Registration::new()))
        }
        fn bridge_ask(&mut self, api: &str, name: &str, data: &str) -> Option<String> {
            let d: Value = serde_json::from_str(data).ok()?;
            let near = d["x"].as_f64()?.abs() <= 16.0 && d["z"].as_f64()?.abs() <= 16.0;
            let op = d["permission"].as_u64().unwrap_or(0) >= 2;
            (api == "extras" && near && !op && (name == "break_block" || name == "use_block"))
                .then(|| "cancel The spawn area is protected".to_owned())
        }
    }
    horizon_mod_sdk::export_server_mod!(Guard);

    manifest: api = "0.3", side = "server", capabilities = ["players","bridge"],
              experimental = ["bridge"]; Cargo.toml adds serde_json = "1".

11.2 Server: a sidebar for every player who joins

    fn init() -> ... { bridge::call("extras","subscribe",r#"["player_join"]"#)?; ... }
    fn bridge_event(&mut self, api: &str, name: &str, data: &str) {
        if api == "extras" && name == "player_join" {
            let d: Value = serde_json::from_str(data).unwrap_or_default();
            let args = serde_json::json!({"player": d["player"], "title": "My Server",
                "lines": ["Welcome!", {"left": "Online", "right": "yes"}]});
            let _ = bridge::call("extras", "sidebar", &args.to_string());
        }
    }

11.3 Client: a one-tap "Potato" performance button (video-settings, short)

    use serde_json::json;   // with horizon_mod_sdk::{Mod, Registration, bridge, export_mod}
    fn init() -> ... { let _ = bridge::call("extras", "options", ""); ...
                       Registration::new().command("potato") }
    fn command(&mut self, _n: &str, _a: &str) -> Result<Option<String>, String> {
        for (name, value) in [("graphics", json!("fast")), ("render_distance", json!(6)),
                              ("max_fps", json!(30)), ("particles", json!(2))] {
            bridge::call("extras", "set_option",
                         &json!({"name": name, "value": value}).to_string())?;
        }
        Ok(Some("Potato settings applied".into()))
    }
    manifest: api = "0.1", side = "client", capabilities = ["command","bridge"],
              experimental = ["bridge"].

# Mod API reference

The contract between Horizon and its mods: the WIT package `horizon:mods@0.1.0`, every interface, type, function and hook in it, and the capabilities a manifest may list. The guide is [mods.md](../mods.md); stability and versions: [stability.md](stability.md). Manifest `api` lines this game serves: `0.1`, `0.2`, `0.3`.

## Capabilities

| In `capabilities` | Grants | The player reads "May …" |
| --- | --- | --- |
| `game-read` | [`game`](#game) | see your position, health and the time |
| `chat` | [`chat`](#chat) | show you chat messages |
| `hud` | [`hud`](#hud) | draw text on your screen |

## `bridge`

Access: capability `bridge`.

Capability `bridge` (experimental, API level 9): APIs that native mods (`.hnmod`) add to the game for sandboxed mods. A native mod names its API (`extras`) and documents its functions, values and events; their arguments and results are text in the form it documents (often JSON). The game needs no new function here for a new API: the native mod serves it, and a mod that uses it loads without rebuilding the game.

| Function | Signature | What it does |
| --- | --- | --- |
| `version` | `func(api: string) -> option<u32>` | The version of `api` a native mod in this game serves; none when no native mod serves it (tell the player which `.hnmod` to install). |
| `get` | `func(api: string, key: string) -> option<string>` | A value `api` published (`native_bridge_publish`), as of the start of this call; none when it published nothing under `key`. |
| `call` | `func(api: string, function: string, args: string) -> result<u64, string>` | Calls `function` of `api` with `args`. The native mod runs it at the start of the next tick, where the game's state is whole; its answer comes back as `bridge-events.reply` with the id this returns, an error when no native mod serves `api`. An error now (nothing queued) for a name over 64 bytes, `args` over 64 KiB, or over 64 calls in one hook. |

//! Example Horizon server mod on the mod bridge's asks: the Extras API native mod
//! (`extras_api.hnmod`, version 2) asks it before a block is broken or used and before an
//! explosion, and it answers `cancel` near the Overworld's 0, 0. Operators (level 2 and up)
//! build there as usual.
use horizon_mod_sdk::bridge;
use horizon_mod_sdk::server::{Registration, ServerMod};
use serde_json::Value;

const API: &str = "extras";
/// The asks it subscribes to.
const ASKS: &str = r#"["break_block","use_block","explosion"]"#;
/// How far from 0, 0 the area reaches, in blocks.
const RADIUS: f64 = 16.0;

struct SpawnGuard;

/// Whether `data` (an ask's JSON) is in the protected area.
fn protected(data: &Value) -> bool {
    let overworld = data["dimension"].as_str() == Some("minecraft:overworld");
    let (x, z) = (data["x"].as_f64(), data["z"].as_f64());
    let near = |v: Option<f64>| v.is_some_and(|v| v.abs() <= RADIUS);
    overworld && near(x) && near(z)
}

/// The answer to an ask: `cancel` with the reason told to the player, or none.
fn answer(name: &str, data: &Value) -> Option<String> {
    if !protected(data) {
        return None;
    }
    match name {
        "explosion" => Some("cancel".into()),
        "break_block" | "use_block" if data["permission"].as_u64().unwrap_or(0) < 2 => {
            Some("cancel The spawn area is protected".into())
        }
        _ => None,
    }
}

impl ServerMod for SpawnGuard {
    fn init() -> Result<(Self, Registration), String> {
        if bridge::version(API).is_none_or(|v| v < 2) {
            horizon_mod_sdk::warn(
                "Spawn Guard needs the Extras API 2 native mod (extras_api.hnmod)",
            );
        } else {
            bridge::call(API, "subscribe", ASKS)?;
        }
        Ok((SpawnGuard, Registration::new()))
    }

    fn bridge_ask(&mut self, api: &str, name: &str, data: &str) -> Option<String> {
        if api != API {
            return None;
        }
        answer(name, &serde_json::from_str(data).ok()?)
    }
}

horizon_mod_sdk::export_server_mod!(SpawnGuard);

#[cfg(test)]
mod tests {
    use super::answer;
    use serde_json::json;
    #[test]
    fn only_the_area_around_spawn_in_the_overworld_is_guarded() {
        let at = |dimension: &str, x: f64, z: f64, permission: u64| json!({"dimension": dimension, "x": x, "z": z, "permission": permission});
        let cancel = Some("cancel The spawn area is protected".to_owned());
        assert_eq!(
            answer("break_block", &at("minecraft:overworld", 3.0, -16.0, 0)),
            cancel
        );
        assert_eq!(
            answer("break_block", &at("minecraft:overworld", 17.0, 0.0, 0)),
            None
        );
        assert_eq!(
            answer("break_block", &at("minecraft:the_nether", 0.0, 0.0, 0)),
            None
        );
        assert_eq!(
            answer("use_block", &at("minecraft:overworld", 0.0, 0.0, 2)),
            None
        );
        assert_eq!(
            answer("explosion", &at("minecraft:overworld", 0.0, 0.0, 0)).as_deref(),
            Some("cancel")
        );
    }
}

//! Example Horizon server mod on the mod bridge (capability `bridge`, API level 9): a sandboxed
//! `.hmod` using an API that a native mod adds. The Extras API native mod (`extras_api.hnmod`)
//! serves `extras`: `command` runs a vanilla command as the server's console, and it publishes the
//! server's `tps` and `mspt`. This mod gives each new player a starter kit with it, and adds `/tps`.
use horizon_mod_sdk::bridge;
use horizon_mod_sdk::server::{Args, Player, Registration, ServerMod, players};
use horizon_mod_sdk::storage;
use std::collections::BTreeMap;

/// The native API this mod uses, and the version it was written for.
const API: &str = "extras";
const VERSION: u32 = 1;
/// The starter kit: item and count.
const KIT: [(&str, u32); 3] = [
    ("minecraft:stone_pickaxe", 1),
    ("minecraft:bread", 8),
    ("minecraft:torch", 16),
];

/// A player's kit on its way: the calls not answered yet.
struct Giving {
    player: String,
    name: String,
    left: usize,
    failed: Option<String>,
}

#[derive(Default)]
struct WelcomeKit {
    /// The ids of the players who got their kit, one per line in storage.
    given: Vec<String>,
    /// By the id `bridge::call` returned: whose kit the call is part of.
    calls: BTreeMap<u64, usize>,
    giving: Vec<Giving>,
}

/// The storage key of the players who got their kit.
const GIVEN: &str = "given";

/// `give Alex minecraft:bread 8`.
fn give_line(name: &str, item: &str, count: u32) -> String {
    format!("give {name} {item} {count}")
}

impl ServerMod for WelcomeKit {
    fn init() -> Result<(Self, Registration), String> {
        let given = storage::get(GIVEN).unwrap_or_default();
        let given = String::from_utf8_lossy(&given)
            .lines()
            .map(str::to_owned)
            .collect();
        Ok((
            WelcomeKit {
                given,
                ..WelcomeKit::default()
            },
            Registration::new().on_joins().command("tps"),
        ))
    }

    fn player_joined(&mut self, player: &Player) {
        if self.given.contains(&player.id) {
            return;
        }
        if bridge::version(API).is_none_or(|v| v < VERSION) {
            players::tell(
                &player.id,
                "No starter kit: this server needs the Extras API native mod (extras_api.hnmod)",
            );
            return;
        }
        let kit = self.giving.len();
        let mut left = 0;
        for (item, count) in KIT {
            if let Ok(id) = bridge::call(API, "command", &give_line(&player.name, item, count)) {
                self.calls.insert(id, kit);
                left += 1;
            }
        }
        self.giving.push(Giving {
            player: player.id.clone(),
            name: player.name.clone(),
            left,
            failed: None,
        });
    }

    fn bridge_reply(&mut self, id: u64, _api: &str, _function: &str, answer: Result<&str, &str>) {
        let Some(kit) = self.calls.remove(&id) else {
            return;
        };
        let giving = &mut self.giving[kit];
        giving.left -= 1;
        if let Err(why) = answer {
            giving.failed.get_or_insert_with(|| why.to_owned());
        }
        if giving.left > 0 {
            return;
        }
        match &giving.failed {
            None => {
                self.given.push(giving.player.clone());
                let _ = storage::set(GIVEN, self.given.join("\n").as_bytes());
                players::tell(
                    &giving.player,
                    &format!("Welcome, {}! Here is your starter kit.", giving.name),
                );
            }
            Some(why) => {
                players::tell(&giving.player, &format!("Your starter kit failed: {why}"));
            }
        }
    }

    fn command(
        &mut self,
        _player: &Player,
        _name: &str,
        _args: &Args,
    ) -> Result<Option<String>, String> {
        match (bridge::get(API, "tps"), bridge::get(API, "mspt")) {
            (Some(tps), Some(mspt)) => Ok(Some(format!("{tps} TPS, {mspt} ms per tick"))),
            _ => Err("Install the Extras API native mod (extras_api.hnmod) for /tps".into()),
        }
    }
}

/// Widget ids: presets from 10, choices from 100, the shader pack 200.
const PRESET_ID: u32 = 10;
const CHOICE_ID: u32 = 100;
const SHADER_ID: u32 = 200;

/// The value after `current` in `choice`, as JSON (the first when `current` is none of them).
fn next(choice: &Choice, current: &Value) -> Value {
    let at = choice
        .values
        .iter()
        .position(|(v, _)| serde_json::from_str::<Value>(v).is_ok_and(|v| same(&v, current)));
    let (v, _) = choice.values[at.map_or(0, |i| (i + 1) % choice.values.len())];
    serde_json::from_str(v).unwrap_or(Value::Null)
}

/// Equal values, numbers by value (`8` and `8.0`).
fn same(a: &Value, b: &Value) -> bool {
    match (a.as_f64(), b.as_f64()) {
        (Some(x), Some(y)) => (x - y).abs() < 1e-6,
        _ => a == b,
    }
}

/// `Label: Value` for the option's current value.
fn label(choice: &Choice, current: &Value) -> String {
    let text = choice
        .values
        .iter()
        .find(|(v, _)| serde_json::from_str::<Value>(v).is_ok_and(|v| same(&v, current)))
        .map(|(_, t)| (*t).to_owned())
        .unwrap_or_else(|| match current {
            Value::String(s) => s.clone(),
            other => other.to_string(),
        });
    format!("{}: {text}", choice.label)
}

/// The `set_option` arguments a preset sends, in order.
fn preset_calls(preset: usize) -> Vec<String> {
    PRESETS[preset]
        .1
        .iter()
        .map(|(name, value)| format!(r#"{{"name":"{name}","value":{value}}}"#))
        .collect()
}

#[derive(Default)]
struct VideoSettings {
    /// The options as the native API last answered, and its shader packs.
    options: Option<Value>,
    packs: Vec<(String, String)>,
    /// The mod's screen is up.
    open: bool,
    /// What went wrong last, shown on the page.
    error: Option<String>,
}

impl VideoSettings {
    fn widgets(&self) -> Vec<Widget> {
        let text = |id, text: &str, color| {
            Widget::Text(TextWidget {
                id,
                text: text.into(),
                color,
            })
        };
        let button = |id, label: String| Widget::Button(ButtonWidget { id, label });
        if bridge::version(API).is_none_or(|v| v < VERSION) {
            return vec![text(
                1,
                "Needs the Extras API 3 native mod (extras_api.hnmod)",
                0xFF5555,
            )];
        }
        let Some(options) = &self.options else {
            return vec![text(1, "Reading the options...", 0xAAAAAA)];
        };
        let mut widgets = vec![text(1, "Presets", 0xFFFF55)];
        for (i, (name, _)) in PRESETS.iter().enumerate() {
            widgets.push(button(PRESET_ID + i as u32, format!("Preset: {name}")));
        }
        widgets.push(text(2, "Options", 0xFFFF55));
        for (i, choice) in CHOICES.iter().enumerate() {
            widgets.push(button(
                CHOICE_ID + i as u32,
                label(choice, &options[choice.name]),
            ));
        }
        let pack = options["shader_pack"].as_str().unwrap_or_default();
        let title = self
            .packs
            .iter()
            .find(|(f, _)| f == pack)
            .map_or(pack, |(_, t)| t.as_str());
        let shown = if pack.is_empty() { "Off" } else { title };
        widgets.push(button(SHADER_ID, format!("Shader Pack: {shown}")));
        if let Some(error) = &self.error {
            widgets.push(text(3, error, 0xFF5555));
        }
        widgets
    }

    fn show(&self) {
        let widgets = self.widgets();
        ui::set_settings(&widgets);
        if self.open {
            ui::open_screen(&Screen {
                title: "Video Settings+".into(),
                widgets,
            });
        }
    }

    fn set(&mut self, args: String) {
        if let Err(e) = bridge::call(API, "set_option", &args) {
            self.error = Some(e);
        }
    }
}

impl Mod for VideoSettings {
    fn init() -> Result<(Self, Registration), String> {
        let _ = bridge::call(API, "options", "");
        let _ = bridge::call(API, "shader_packs", "");
        let me = VideoSettings::default();
        me.show();
        Ok((me, Registration::new().command("video")))
    }

    fn command(&mut self, _name: &str, _args: &str) -> Result<Option<String>, String> {
        self.open = true;
        self.show();
        Ok(None)
    }

    fn ui_settings_opened(&mut self) {
        let _ = bridge::call(API, "options", "");
        self.show();
    }

    fn ui_closed(&mut self) {
        self.open = false;
    }

    fn ui_select(&mut self, id: u32, _row: u32) {
        let Some(options) = &self.options else {
            return;
        };
        self.error = None;
        if (PRESET_ID..PRESET_ID + PRESETS.len() as u32).contains(&id) {
            for args in preset_calls((id - PRESET_ID) as usize) {
                self.set(args);
            }
        } else if let Some(choice) = CHOICES.get(id.wrapping_sub(CHOICE_ID) as usize) {
            let value = next(choice, &options[choice.name]);
            self.set(json!({"name": choice.name, "value": value}).to_string());
        } else if id == SHADER_ID {
            let current = options["shader_pack"].as_str().unwrap_or_default();
            let files: Vec<&str> = std::iter::once("")
                .chain(self.packs.iter().map(|(f, _)| f.as_str()))
                .collect();
            let at = files.iter().position(|f| *f == current).unwrap_or(0);
            let pick = files[(at + 1) % files.len()];
            self.set(json!({"name": "shader_pack", "value": pick}).to_string());
        }
    }

    fn bridge_reply(&mut self, _id: u64, api: &str, function: &str, answer: Result<&str, &str>) {
        if api != API {
            return;
        }
        match (function, answer) {
            ("options" | "set_option", Ok(json)) => {
                self.options = serde_json::from_str(json).ok();
            }
            ("shader_packs", Ok(json)) => {
                let packs: Vec<Value> = serde_json::from_str(json).unwrap_or_default();
                self.packs = packs
                    .iter()
                    .map(|p| {
                        let file = p["file"].as_str().unwrap_or_default().to_owned();
                        let title = p["title"].as_str().unwrap_or(&file).to_owned();
                        (file, title)
                    })
                    .collect();
            }
            (_, Err(why)) => self.error = Some(why.to_owned()),
            _ => {}
        }
        self.show();
    }
}

#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn choices_cycle_from_the_current_value_and_wrap() {
        let render = &CHOICES[0];
        assert_eq!(next(render, &json!(8)), json!(10));
        assert_eq!(next(render, &json!(32)), json!(2));
        // A value the list doesn't have starts it over.
        assert_eq!(next(render, &json!(7)), json!(2));
        let clouds = &CHOICES[4];
        assert_eq!(next(clouds, &json!("fast")), json!("true"));
        assert_eq!(label(clouds, &json!("true")), "Clouds: Fancy");
        let brightness = &CHOICES[10];
        assert_eq!(label(brightness, &json!(5.0)), "Brightness: Fullbright");
        assert_eq!(label(brightness, &json!(0.7)), "Brightness: 0.7");
    }
    #[test]
    fn presets_set_the_graphics_preset_first() {
        let potato = preset_calls(0);
        assert_eq!(potato[0], r#"{"name":"graphics","value":"fast"}"#);
        assert!(potato.contains(&r#"{"name":"max_fps","value":30}"#.to_owned()));
        for call in potato
            .iter()
            .chain(&preset_calls(1))
            .chain(&preset_calls(2))
        {
            assert!(serde_json::from_str::<Value>(call).is_ok(), "{call}");
        }
    }
}
